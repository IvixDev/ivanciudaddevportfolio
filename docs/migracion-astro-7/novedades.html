01 · Lo que te aporta

Novedades que sí notarás

Solo las que tienen sentido en un sitio estático de 12 páginas, sin servidor ni contenido en Markdown.

Astro 7.0 · Vite 8

Builds más rápidos

El compilador de .astro pasa de Go a Rust y Vite 8 empaqueta con Rolldown. Astro midió en su web (unas 300 páginas) una bajada de 62,7 s a 24,2 s.

Para ti: CI y despliegues de Vercel más cortos. Lo mediremos con 12 páginas; no se asume la misma cifra.

Astro 7.0

HTML válido obligatorio

El nuevo compilador ya no “arregla” etiquetas sin cerrar ni un <div> dentro de un <p>: falla el build.

Para ti: el HTML que leen Google y los lectores de pantalla es el que escribiste. Encaja con tu prioridad de SEO y accesibilidad.

Astro 7.4

astro build --timings

Un resumen al final del build que dice qué tarda: integraciones, imágenes, sitemap…

Para ti: cumple la regla de AGENTS.md: medir antes de optimizar.

Astro 6+ · opcional

API de fuentes

fonts y <Font preload /> descargan y sirven Onest, Bricolage y JetBrains Mono desde tu dominio, con preload automático y fuentes de reserva ajustadas a sus métricas.

Para ti: menos saltos de layout al cargar la fuente (CLS) y 3 dependencias menos.

Astro 7.2 – 7.3

Dev y preview más cómodos

astro preview --background e --ignore-lock, HMR de estilos más estable y un dev server que no reevalúa todo en cada petición.

Para ti: Lighthouse y pruebas en local sin pelearte con procesos y puertos.

Mantenimiento

Al día y con soporte

Astro 5 ya no recibe novedades. Con 7.4, sharp 0.35 (mejor AVIF), Vite 8 y Zod 4 vuelves a la rama con soporte y arreglos de seguridad.

Para ti: las próximas actualizaciones son minor, no otro salto de dos majors.

02 · Lo que cambia respecto a tu petición

React 19.1 y TypeScript 7.0

Entiendo que el “7.0” se refiere a TypeScript 7.0, la versión nativa. Ninguno de los dos saltos conviene ahora.

⚠ React 19.1

Ya tienes una versión más nueva

  • El proyecto usa React 19.2.9. Pasar a 19.1 sería un downgrade.
  • Tras el rediseño, React solo pinta en servidor los iconos de tabler. No hay islas client:*, así que el visitante no descarga React.
  • @astrojs/react 7.1 acepta cualquier React 19.

Recomendación: mantener 19.2.x. Mejor aún, en un PR aparte, quitar React y usar los SVG de @tabler/icons directamente en Astro.

✕ TypeScript 7.0

Bloqueado por las herramientas de Astro

  • @astrojs/check 0.9.10 solo admite TS 5 y 6. Desde Astro 7.3.4, astro check avisa de que TS 7 no está soportado.
  • Solo hay una vía experimental con TS 7.1, que aún está en desarrollo, y @astrojs/ts-content-mapper.
  • typescript-eslint pide <6.1.

Recomendación: TypeScript 6.0.3 ahora y TS 7.1 cuando lo soporten Astro y typescript-eslint.

05 · Antes de cada PR

Cómo sabremos que nada se ha roto

Todo con Node 24, el mismo que usan la CI y Vercel.

  • pnpm lint, pnpm test (29 tests) y pnpm build con astro check limpio.
  • Diff del HTML de dist/ contra la línea base: canonical, hreflang, JSON-LD y preloads intactos.
  • Sitemap idéntico y sin JS de React en el cliente (≈ 5 kB gzip en total).
  • Lighthouse en las 8 rutas: Accesibilidad 100, SEO 100 y Performance ≥ 98.
  • Revisión visual a 320, 768, 834 y 1440 px en ES y EN, sin scroll horizontal.
  • Cambio de idioma: sin animaciones repetidas, header estable y scroll conservado.
  • astro build --timings y tiempo de build frente a la línea base.
  • pnpm install --frozen-lockfile sin avisos de dependencias peer.
